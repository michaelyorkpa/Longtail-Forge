Tasks is a first-party Longtail Forge module. Tasks can be scoped to a workspace, client, or project depending on the active workspace and available modules. A task has a title, status, priority, assignees, an optional estimate, optional due date and time, and optional client or project context.

The Tasks page supports single-task editing and selected-task bulk changes. Bulk edit can update status, priority, Project, assignees, due date, due time, and tags. Project assignment requires a Project; in Business workspaces, choose a Client scope to narrow the Project list, while Personal and Family workspaces remain Project-only. Due date and due time can be set or cleared separately; clearing a due date also clears the due time because a task cannot keep a due time without a date. Blocking one or several tasks requires a Blocked Reason. When selected tasks have mixed Projects, due dates, due times, or tags, the page shows an in-app confirmation before applying the change. The tag filter accepts typed searches and keyboard selection from suggestions.

The Add/Edit Task dialog keeps the title and a compact metadata ribbon near the top. An always-visible continuity row keeps Resume note and Next action together, with Blocked Reason appearing in its third column only while the task is blocked. The collapsible Task Details grid groups Status, Priority, and Estimate; Client, Project, and Parent Task; Due Date and Due Time; then Description and Assignees. Estimates are optional and use 15-minute increments; they describe expected effort but do not schedule the Task automatically. Duplicated Tasks and future recurring occurrences keep the saved estimate. New child tasks can inherit the parent's schedule, priority, and empty Client/Project context; completed and archived tasks are not offered as new parents. When a parent Task moves to another Project, all of its descendants move with it. Task rows nest visible children under their parent and provide a clickable `Child of:` chip. Blocked Reason remains required when the task is blocked. Checklist and Assignees start collapsed unless they already contain checklist items or selected assignees. Enter adds or saves the focused checklist item without closing the task. In a custom Reminders override, the second timed and date-only reminders each have an Enabled checkbox; clear it when that extra notification is not useful.

The task heading bell follows or unfollows notifications for the task; a red bell means notifications are enabled for that task. On an existing editable Open or In Progress Task, an icon-only Block action sits immediately left of Complete and asks why the Task is now blocked before saving the transition. Both actions are permission- and status-gated; Complete remains immediately left of Open in Workbench. Footer icons open task tags and files inside the task workflow and copy the task link. Parent Task choices follow the parent-before-child hierarchy with hyphen-prefix indentation. Save records Add or Edit changes and keeps the dialog open, while Save & Close records them and exits; Cancel exits without another save. Those icon buttons keep accessible labels and hover titles even when the visible button text is hidden.

Task permissions control who can view, create, edit, assign, complete, archive, restore, or attach files to tasks. Users may see only the tasks allowed by their role scope.

When Tasks and Time Tracking are both enabled, eligible Open or Blocked Tasks can start task timers and move to In Progress. Checking a checklist item also moves a Blocked Task to In Progress; either action clears the active Blocked Reason. If timer start was the only thing that caused that change, Reset restores the exact prior Blocked state and reason. Reset does not restore Blocked when checked checklist work or saved task time still shows that work has started, and saving the timer as a normal time entry keeps the Task In Progress. Unchecking the last checklist item returns an In Progress task to Open only when there is no running or paused task timer, saved task time, or other checked item showing that work has started. Completed tasks can show a compact `TTC:` duration chip after completion metadata is saved.

When a recurring task is completed, Tasks shows `Next scheduled` while the next occurrence is created in the background. Once it is ready, `Open next task` goes directly to that occurrence. If the series has no future date, Tasks says that the recurring series ended. Future checklist steps start unchecked, and a Blocked Reason entered on one occurrence does not carry into the recurrence template or later occurrences.
