Tasks are commitments and outcomes. A task can carry a next action, blocked reason, resume note, due date and time, assignees, tags, files, checklist progress, parent/child relationships, recurrence, reminders, and timer state.

Use Next action for the immediate step, Blocked reason when work cannot continue, and Resume note for where the work paused. Focus Selection shows a saved handoff in the Start here card as `Resume note: <note>`. Opening that Task in Task Focus clears the saved note so the next focus session can create a fresh handoff; clearing it does not change the Task's current status.

Leaving an Open or In Progress Task Focus may ask `Add resume note?`, whether or not the Task uses a timer or checklist. A Task in Blocked status, or one with a Blocked Reason, does not request a Resume note when focus changes. Enter one line and choose Yes to save it and mark eligible work In Progress. Choose No to continue without a write; an Open Task therefore stays Open. If a refresh or hard exit cannot show the question safely, Workbench may offer it once when you return after confirming the Task still qualifies and is not blocked. Pausing or saving a Task timer can also offer the same optional handoff after the timer action completes when the Task has no blocked context.

Choosing Block from a Task row, Workbench, or the Task editor asks `Why is the task now blocked?`; Continue saves the Task as Blocked with that reason, while Cancel leaves its previous status unchanged. Bulk Block uses the same prompt when its optional reason field is blank. When a Task becomes Blocked from any source, all running timers linked to it pause automatically and retain their elapsed time. A Blocked Task shows a Play/Resume control on its row, in the Task editor, and in the Workbench Task Focus header; choose it to move the Task to In Progress and clear the Blocked Reason. Starting or resuming its timer, or checking a checklist item, does the same automatically. In the task dialog, Next Action and Resume Note appear together, while Blocked Reason appears only when the task is blocked. Checklists keep lightweight progress inside the task and start collapsed unless the task already has checklist items; Enter adds or saves the focused checklist item. Parent/child task links can show when incomplete child work is blocking a parent task, and list rows can nest children beneath a visible parent with a clickable `Child of:` link. Completed and archived tasks remain readable history and are not treated as active resume candidates by default.

Completed tasks can show a compact `TTC:` duration chip after the completed task has saved completion metadata. Selecting a completed status before saving does not create the duration chip by itself.

Completing a Task finishes the action without opening or holding the Task editor at Next Action. Completion from the editor closes it, completion from the Tasks list refreshes the list, and completion from Workbench returns to Focus Selection. An existing Next Action stays on the completed Task as ordinary context but does not create a Workbench follow-up or make the Task active again.

For a recurring Task, completing an unchanged occurrence does not ask whether to update only this Task or all future Tasks. An occurrence-only change such as Next Action also saves without that question. If you changed the recurring template itself—for example its title, due schedule, assignees, or recurrence rule—the editor asks `Only This Task` or `All Future` once, then completes normally.

Completing a recurring task shows its next scheduled date even when the future occurrence is still too far away to appear in normal Workbench recommendations. The message becomes an `Open next task` action after background creation finishes. If a recurring checklist template was empty, the completing task's checklist labels and order seed future occurrences once; future checked state always starts clear. Blocked Reason stays on the occurrence where it was entered and is never copied to the recurrence template or later occurrences.

Tasks expose this context through task reads, summaries, Workbench task items, search, audit, and internal task event metadata. Resume-state rows use the task's safe context fields and read checks so completed, archived, inaccessible, or hidden task records do not appear as active work to resume.
