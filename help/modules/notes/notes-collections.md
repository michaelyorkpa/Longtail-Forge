Collections organize notes inside one Library bucket. A collection can have child collections, and a note can belong to one current collection.

Collections are classification metadata. They do not grant access, expose private or secure notes, replace linked clients or projects, or make a note visible to someone who cannot otherwise read it. Collection counts are permission-filtered, and archived collections stay out of the normal tree unless they are explicitly included.

The Notes module settings page calls this same Collection hierarchy **Catalogs** in its management box. That wording does not create a second hierarchy: creating, editing, archiving, or restoring a Catalog changes the existing Notes Collection tree.

Current catalog/collection membership does not add inherited security. Secure protection remains an explicit note-level choice. Moving a normal note into a Collection does not encrypt it, and moving a Secure Note does not remove its existing protection.
