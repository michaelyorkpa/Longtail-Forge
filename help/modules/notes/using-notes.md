Notes are internal working records. A note can stand alone in the Notes Library or link to a client, project, task, ticket, or user when that context helps explain the work.

Each note has a title, Markdown body, Library bucket, status, owner, optional linked context, tags, files, and revision history. Business workspaces can also choose Internal, Private, Workspace, Client Visible, or Public visibility. Family workspaces can choose Internal, Private, Workspace, or Public; Client Visible does not apply. Personal workspaces do not show visibility choices because every note uses the same personal default. Notes follow the same module-state and permission checks as the rest of Longtail Forge, so a Library bucket, collection, tag, or linked record never grants access by itself.

To update several notes at once, select their checkboxes in Notes List and open Bulk Edit. You can change Library, Collection, and Note Kind while leaving any other field unchanged. Family and Business workspaces can also change the applicable Visibility choices; Personal workspaces do not show that field. You can also add, remove, or replace direct tags: choose the Tag Action, then type to search and select existing tags. Choosing a collection also moves the notes into that collection's Library. Changing Library without choosing a collection moves the selected notes to Uncategorized. Archived notes must be restored before editing, and every selected note still goes through its normal access checks.

Users with both Manage Notes Settings and Manage Notes Library permissions can open Settings -> Admin -> Modules -> Notes. The Catalog Management box lists the Collections used by the Notes Library, including archived entries. Create or edit one catalog at a time, or select up to 100 catalogs to archive or restore together. Selecting a parent and its child archives that subtree once; restoring selected catalogs processes parents first. If some selections cannot be updated, the successful changes remain and the failed selections stay selected so you can recover without rebuilding the list.

Users who also have Manage Secure Notes can enable catalog security from its separate Security action. The Security column distinguishes explicit protection from protection inherited through a parent; inherited protection cannot be weakened at the child. Review the preflight counts before enabling security. A large transition may continue in the background, and the page refreshes its status automatically. If a transition reports recovery needed, correct the safe blocker shown by the page and choose Retry Security; the catalog remains protected while recovery is pending. Removing security is a separate destructive action that requires your current password and the exact catalog ID. Explicitly secure notes and independently protected child trees remain secure. These controls do not display or change Secure Notes keys.

When creating a note, Save keeps the dialog open and converts it to Edit Note after the record is persisted. Saved-note tools such as Copy Link, notification following, Tags, and Files then become available without reopening the note. Choose Save & Close when you want to commit the note and leave the dialog immediately.
