## Reviewed repository adoption

The emitted files need no repair, but the module is not fully adopted into this repository until the reviewed adoption checklist is complete. The durable guide, with the two companion steps this list does not name and the evidence model, is "Adopt A Generated Module Into This Repository" in `docs/module-development.md`.

These steps are performed through normal review, not automatically by `module:create`:

- Update the reviewed API scope inventory AND `docs/public-api.md`.
- Update the module IDs, normalized manifest baseline, and activated search-indexer inventory.
- Update the public-demo inventory/count without relaxing capability restrictions.
- Classify the routes explicitly for Support View. A generated GET route is not automatically Support-View safe.
- Supply a reviewed default-grant migration, the consolidated-baseline seed update, and generated-schema refresh. `npm run db:schema:refresh` refreshes `current.generated.sql`; it does not by itself supply the required `current.sql` seed changes. A manifest default alone does not prove database migration convergence.

The manifest already provides a declared inline Help article. Switching to first-party Markdown Help is a separate reviewed change: declare a manifest `contentPath` under `help/modules/__ID__/`, link it from `help/toc.md`, and add the relevant Help-layout inventory entry. Creating a Markdown file alone does not make it reachable.
